# 语义视图（Live View）

把解析结果**实时绘制成网页版游戏界面**：不是树，是按游戏真实坐标重构的
画面——窗口在它该在的位置，总览行带着原生 bracket 图标，模块按钮用
游戏图标，悬停任意元素看全部语义细节。

```bash
eve-view --pid 31336                 # 活体客户端 → http://127.0.0.1:8765
eve-view --pid 31336 --open          # 自动开浏览器
eve-view --sample dump.zip           # 离线样本回放（无需开游戏，画面静态）
```

或从 Python：

```python
import eve_proxy_ng
eve_proxy_ng.serve_view(pid=31336, port=8765, open_browser=True)  # 阻塞
```

## 看到什么

- **窗口层**：Overview/库存/装配/站内窗口的边框与标题
- **总览层**：条目行 = bracket 原生图标 + 名称 + 金色距离；被遮挡行红框
- **模块层**：高/中/低槽按钮（游戏图标；激活=绿框、忙碌=金框）+ 侧边
  电容/护盾/装甲/结构条 + 速度
- **菜单层**：右键菜单/工具菜单（勾选状态如实显示）
- **交互元素层**：全部可点击元素的框线（青=可交互、虚线灰=普通、
  红=被遮挡），带文本标签

**悬停任意元素**显示语义细节：类型/名称/角色（role）/typeID/图标名/
地址/遮挡率——与 `interaction_elements` 字段一一对应。顶栏可按层开关、
暂停，并显示实时统计（节点数/构建耗时/更新速率/游戏状态）。

## 技术与边界

- **零依赖**：纯标准库 HTTP + SSE（Server-Sent Events）推送场景流，
  无需额外安装任何 Python 包；单文件 Canvas 前端
- 数据流：服务器按 `--interval-ms`（默认 250）轮询
  `read_snapshot()`，投影成紧凑场景（约 50-150KB/帧）推给浏览器；
  图标字节经 `/icon` 端点按需加载（内存缓存），来自游戏共享缓存
- 坐标即游戏客户区坐标，画布 1:1，浏览器内自动缩放适配
- 样本模式下图标需要本机存在共享缓存（或有运行中客户端）才能加载，
  否则画占位框
- 仅监听 `127.0.0.1`（本机工具，不做鉴权）；勿暴露到公网
